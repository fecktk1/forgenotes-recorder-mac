# September 2026 security release

Electron 43.6.0 updates the browser/media engine while preserving macOS 12 compatibility. Dependency audits must pass without exceptions. Native CI checks microphone encoding, separate synthesized system audio, room capture, pause/resume, and decoded output, plus recording recovery contracts and capture timing (`npm run test:capture-runtime`: a simulated sleep is left out of segment durations, and stop on silence asks and then stops a silent recording). The recorder window is driven through both call-audio paths with stand-in streams (`npm run test:recorder-ui`: native capture on macOS 14.2 and later, including permission refused, unanswered and late, a track lost and reopened mid-recording, and the BlackHole path on macOS 13), and `npm run verify:mac` checks that the app declares its own microphone and call-audio permission sentences and that the app and every helper carry the audio-input entitlement. These are synthetic checks and do not validate physical devices, routing, or what macOS actually hands over.

Manual workflow dispatch defaults to a draft release. Promote only after testing physical microphone and system audio separately and together (on macOS 14.2 or newer: the first-run "Allow call audio" window, a refusal turned back on in System Settings, and a change of sound output mid-recording; on macOS 12.0 to 14.1, or with the setting: BlackHole), a long recording, pause/resume, sleep/wake (close the lid mid-recording for a few minutes: the meeting's length leaves the sleep out and its start is when Start was pressed), stop on silence (set to 5 minutes: the chime, notification and Dock bounce at 4 minutes, Keep recording from the notification, and the stop at 5 minutes), authentication, upload and retry, and installation/update on the supported OS. macOS additionally requires live captions/model loading and both supported architectures. Store APPX submission is a separate release step; do not replace a pending submission automatically.

Sign in with SSO (only offered when `forgenotes_sso_available()` is true): with a real identity provider on the signed, notarized build, the browser opens the provider, finishing there brings the app forward signed in (also with the window closed and the app only in the Dock, and with the app not running at all, which says to start again), quit and relaunch keeps you signed in, Cancel and a refused sign-in (a user not assigned to the app at the provider) show a sentence, and a domain with no provider says single sign-on is not set up. `npm test` covers the callback parser, the PKCE pair and verifier handling; `npm run test:sso-runtime` signs the real app in against a fake auth server; `npm run verify:mac` checks that Info.plist declares the `forgenotes-recorder` scheme.

Record the tested OS, device/routing, version, and results with the release before promotion. A draft's auto-update metadata is not served as the latest public release.
